# Chapter 19: Agent Scoring and Behavioral Assessment

## 19.1 Agent Architecture Overview

The PALLADIUM NULL agent system is composed of modular software agents that operate within the digital twin environment. Each agent is designed to interact with simulated civil-defense infrastructure, monitor hazard events, and produce behavioral assessments that quantify performance against a predefined set of civil-defense criteria. The architecture is deliberately constrained: agents are purely evaluative and receive-only, consuming data streams generated by the world simulator without any capacity to transmit toward or influence targets.

Every agent in the PALLADIUM NULL framework is scored on its civil-defense performance using a behavioral assessment function. This function aggregates multiple scoring dimensions into a single weighted composite score. The scoring is purely evaluative — it measures how well an agent performs its civil-defense role and does not incorporate any offensive or targeting metrics. This is a foundational design principle that distinguishes the PALLADIUM NULL architecture from conventional multi-agent systems.

The agents operate on the receive-only principle: they consume data from the digital twin, process it through the scoring pipeline, and emit assessment outputs that are logged for observability. No agent in the system is capable of initiating a transmission toward a target coordinate, computing an intercept trajectory, or generating a fire-control solution. The receive-only constraint is enforced at the source code level, and any violation triggers a compliance flag that zeros the agent's compliance score.

The agent loop follows a deterministic cycle: observe the digital twin state, score the agent's behavioral dimensions against the assessment function, act within the permitted verb set, and re-evaluate on the next tick. This loop is illustrated in Figure {{FIG:fig-agent-loop|Agent loop: observe, score, act, re-evaluate}}. The loop is entirely passive — the agent observes the world state, evaluates its own performance, and emits civil-defense verbs such as SHOW, HOLD, WARN, and SHELTER. No agent can emit a targeting vector, a launch command, or any geometry intended for weapon delivery.

The source-level implementation of the scoring function resides in the agent module. The core evaluation logic is defined as a function that takes the agent's internal state and the current world snapshot, then returns a structured score object. Below is the TypeScript function signature that captures the essential contract:

```typescript
function scoreAgentBehavior(state: AgentState, world: TwinSnapshot): BehavioralScore {
  const coverage = computeCoverage(state, world);
  const accuracy = computeAccuracy(state, world);
  const timeliness = computeTimeliness(state, world);
  const compliance = computeCompliance(state, world);
  return { coverage, accuracy, timeliness, compliance, total: weightedSum(coverage, accuracy, timeliness, compliance) };
}
```

This function is the central mechanism by which agent behavior is quantified. Each sub-function — `computeCoverage`, `computeAccuracy`, `computeTimeliness`, and `computeCompliance` — evaluates a distinct dimension of civil-defense performance. The `weightedSum` function combines these dimension scores using predefined weights that reflect the relative importance of each dimension in the civil-defense context. The output is a `BehavioralScore` object where every field is labeled with the constraint string `SANDBOX CIVIL DEFENSE ONLY`, ensuring that all scoring outputs are explicitly categorized as civil-defense evaluations.

The modular design of the agent system means that each agent can be independently assessed without affecting the operation of other agents. This modularity is critical for the multi-agent simulation environment, where dozens of agents may be running simultaneously, each evaluating different aspects of the civil-defense scenario. The scoring function provides a common framework that allows for consistent comparison across agents, regardless of their specific role or domain of operation.

The architecture is documented with explicit cross-references to related chapters. Chapter 16 (world simulator) describes the digital twin environment from which agents consume data. Chapter 20 (shelter role gating) details the verb emission constraints that shape the action space available to scored agents. Chapter 21 (log observability) covers the logging infrastructure that records every scoring event for post-simulation analysis. Together, these chapters form a complete picture of the agent lifecycle from data ingestion through behavioral assessment to output logging.

## 19.2 Scoring Dimensions

The behavioral assessment function evaluates agents across four primary dimensions: coverage, accuracy, timeliness, and compliance. Each dimension captures a distinct aspect of civil-defense performance, and each is assigned a weight that reflects its importance in the overall assessment. The weighted combination of these dimensions yields the total agent score, which ranges from 0.0 (complete failure) to 1.0 (perfect performance).

The scoring dimensions and their associated weights are summarized in Table {{TABLE:tab-agent-params|Agent scoring parameters and weights}}. These weights are configurable parameters that can be adjusted based on the specific civil-defense scenario being simulated, but the default values provide a balanced assessment framework that has been validated against the operational requirements of the PALLADIUM NULL system.

| Dimension | Symbol | Weight | Description |
|-----------|--------|--------|-------------|
| Coverage | C | 0.30 | Fraction of shelter-relevant events correctly identified |
| Accuracy | A | 0.30 | Precision of event localization in the city plane |
| Timeliness | T | 0.20 | Speed of actionable alert production relative to threshold |
| Compliance | P | 0.20 | Adherence to SANDBOX CIVIL DEFENSE ONLY constraint |

**Coverage** measures how well an agent identifies shelter-relevant events within its operational area. An event is considered shelter-relevant if it poses a direct threat to civilian populations and requires a shelter response. The coverage score is computed as the ratio of detected shelter-relevant events to the total number of such events within the agent's monitoring range. A coverage score of 1.0 indicates that the agent detected every shelter-relevant event; a score of 0.0 indicates that none were detected. The coverage dimension is weighted at 0.30, reflecting its fundamental importance in ensuring that no threat goes unnoticed.

**Accuracy** measures how precisely an agent localizes the source of a detected event. Unlike coverage, which is a binary detection metric, accuracy is a continuous measure that quantifies the spatial precision of the agent's reporting. The accuracy score is derived from the Euclidean distance between the true event location and the agent's reported location, mapped through a decaying function that produces a score between 0.0 and 1.0. The accuracy dimension is also weighted at 0.30, reflecting the critical importance of precise localization for effective shelter placement and population routing.

**Timeliness** measures how quickly an agent produces an actionable alert after detecting an event. The timeliness score is computed as a function of the delay between event detection and alert issuance, normalized against a predefined threshold. If the delay is zero, the timeliness score is 1.0; if the delay equals the threshold, the score is 0.0; and if the delay exceeds the threshold, the score is clamped to 0.0. The timeliness dimension is weighted at 0.20, reflecting the importance of rapid response in civil-defense scenarios where every second counts.

**Compliance** measures whether the agent adheres to the SANDBOX CIVIL DEFENSE ONLY constraint throughout its operation. This is a binary or hard constraint dimension: if the agent performs any operation that violates the constraint — such as computing a targeting vector, generating an intercept solution, or attempting to transmit toward a target — the compliance score is set to 0.0. If the agent operates entirely within the permitted scope, the compliance score is 1.0. The compliance dimension is weighted at 0.20, reflecting the foundational role that constraint adherence plays in the overall safety and legitimacy of the agent system.

The total weighted score is computed as:

```
Total Score = (C × w_C) + (A × w_A) + (T × w_T) + (P × w_P)
            = (C × 0.30) + (A × 0.30) + (T × 0.20) + (P × 0.20)
```

where C, A, T, and P are the dimension scores (each in [0.0, 1.0]) and w_C, w_A, w_T, w_P are the corresponding weights. The maximum possible total score is 1.0, achieved when all dimensions score perfectly. The minimum is 0.0, achieved when all dimensions fail or when compliance is violated.

The scoring function is designed to be extensible. Additional dimensions can be added by introducing new sub-functions and adjusting the weight vector accordingly. However, the current four-dimension framework has been carefully chosen to cover all critical aspects of civil-defense agent performance without introducing unnecessary complexity. The weights have been tuned through simulation studies that balance the competing demands of detection, precision, speed, and safety.

## 19.3 Worked Example 19.1 — Coverage Scoring

Consider an agent deployed to monitor FM broadcast illuminators across a 100 km radius in the MERIDIAN BAY metropolitan area. The agent's coverage assessment function scans the digital twin for all FM broadcast stations within its operational radius and determines which of these stations have been successfully detected and incorporated into the shelter alert network.

In this scenario, there are 20 FM broadcast stations within the agent's 100 km monitoring radius. Of these 20 stations, the agent successfully detects and integrates 15 into its shelter alert network. The remaining 5 stations are either outside the agent's detection sensitivity, occluded by terrain features, or experiencing signal degradation that prevents reliable identification.

The coverage score is computed as the ratio of detected stations to the total number of stations within range:

```
Coverage = Detected / Total
Coverage = 15 / 20
Coverage = 0.75
```

This yields a raw coverage score of 0.75, meaning that the agent has identified 75% of the shelter-relevant FM broadcast stations within its operational area. Each detected station contributes to the shelter alert network by providing a redundant communication pathway that can be used to relay civil-defense warnings to the civilian population.

To obtain the weighted coverage contribution to the total agent score, the raw coverage score is multiplied by the coverage weight:

```
Weighted Coverage = Coverage × w_C
Weighted Coverage = 0.75 × 0.30
Weighted Coverage = 0.225
```

The weighted coverage score of 0.225 is out of a maximum possible contribution of 0.30. This means that the agent has earned 75% of the available coverage points, which represents a strong but not perfect performance in the coverage dimension. The 5 undetected stations represent gaps in the shelter alert network that could potentially compromise civil-defense communication in the event of an actual hazard.

The coverage assessment function continues to monitor the FM broadcast illuminators on each subsequent tick. If the agent detects additional stations or if signal conditions improve, the coverage score may increase on future evaluations. Conversely, if station failures or terrain occlusion worsens, the coverage score may decrease. The dynamic nature of the coverage score ensures that the agent's behavioral assessment reflects real-time changes in the operational environment.

For comparison, an agent that detected all 20 stations would achieve a coverage score of 20/20 = 1.0 and a weighted coverage contribution of 1.0 × 0.30 = 0.30, the maximum possible in this dimension. The gap between 0.225 and 0.30 quantifies the performance deficit that the agent must address through improved detection sensitivity or expanded monitoring range.

## 19.4 Worked Example 19.2 — Accuracy Scoring

Consider an agent that is tasked with localizing a simulated seismic event within the MERIDIAN BAY city plane. The true location of the seismic event, as recorded by the world simulator, is at coordinates (5.0, 3.0) km. The agent processes the sensor data and reports the event location as (5.2, 3.1) km. The accuracy of the agent's localization is assessed by computing the Euclidean distance between the true coordinates and the reported coordinates.

The error calculation proceeds as follows:

```
Error = √((x_reported - x_true)² + (y_reported - y_true)²)
Error = √((5.2 - 5.0)² + (3.1 - 3.0)²)
Error = √((0.2)² + (0.1)²)
Error = √(0.04 + 0.01)
Error = √(0.05)
Error = 0.2236 km
```

The Euclidean error is 0.2236 km, which represents the straight-line distance between the true event location and the agent's reported location in the city plane. This metric is appropriate for civil-defense assessment because it captures the spatial precision of the agent's localization in a single scalar value that can be directly interpreted by civil-defense operators.

The accuracy score is then computed using a decaying function that maps the error to a score between 0.0 and 1.0:

```
Accuracy = 1 / (1 + Error)
Accuracy = 1 / (1 + 0.2236)
Accuracy = 1 / 1.2236
Accuracy = 0.817
```

The accuracy score of 0.817 indicates that the agent's localization is reasonably precise, falling within approximately 224 meters of the true event location. The decaying function ensures that small errors are penalized gently while large errors are penalized more severely. An agent that reported the event location exactly at (5.0, 3.0) would achieve an accuracy score of 1 / (1 + 0) = 1.0, the maximum possible.

To obtain the weighted accuracy contribution to the total agent score, the raw accuracy score is multiplied by the accuracy weight:

```
Weighted Accuracy = Accuracy × w_A
Weighted Accuracy = 0.817 × 0.30
Weighted Accuracy = 0.2451
```

The weighted accuracy score of 0.2451 is out of a maximum possible contribution of 0.30. This means that the agent has earned approximately 81.7% of the available accuracy points, reflecting its high-precision localization capability.

The error metric used here is the Euclidean distance in the city plane, which is defined as:

```
d = √((Δx)² + (Δy)²)
```

where Δx and Δy are the differences between the reported and true coordinates in the east-west and north-south directions, respectively. This metric is chosen because the MERIDIAN BAY city plane is approximately flat over the scales involved in civil-defense operations, making the Euclidean distance a valid approximation of the true spatial separation.

For context, the coverage and accuracy scores computed in Examples 19.1 and 19.2 together contribute:

```
Coverage + Accuracy (weighted) = 0.225 + 0.2451 = 0.4701
```

This partial total of 0.4701 out of a possible 0.60 from the coverage and accuracy dimensions alone demonstrates that the agent is performing well on the two most heavily weighted dimensions. The remaining dimensions — timeliness and compliance — will determine whether the agent achieves a passing overall score.

## 19.5 Worked Example 19.3 — Timeliness Scoring

Consider the same agent from Examples 19.1 and 19.2. The agent has detected a shelter-relevant event and localized it with acceptable accuracy. The critical question now is how quickly the agent produced its actionable alert after detection. In this scenario, the event was detected at time t = 0 seconds, and the agent issued its alert at time t = 45 seconds.

The timeliness threshold for actionable alerts in the PALLADIUM NULL civil-defense framework is 60 seconds. This threshold represents the maximum acceptable delay between event detection and alert issuance, beyond which the alert loses its operational value for shelter activation and population protection.

The timeliness score is computed as:

```
Timeliness = max(0, 1 - (Delay / Threshold))
Timeliness = max(0, 1 - (45 / 60))
Timeliness = max(0, 1 - 0.75)
Timeliness = max(0, 0.25)
Timeliness = 0.25
```

The timeliness score of 0.25 indicates that the agent took 75% of the allowable time budget to produce its alert. The delay of 45 seconds is well within the 60-second threshold, so the score is not clamped to 0.0. However, the score is relatively low, reflecting the significant portion of the time budget that was consumed.

To obtain the weighted timeliness contribution to the total agent score, the raw timeliness score is multiplied by the timeliness weight:

```
Weighted Timeliness = Timeliness × w_T
Weighted Timeliness = 0.25 × 0.20
Weighted Timeliness = 0.05
```

The weighted timeliness score of 0.05 is out of a maximum possible contribution of 0.20. This means that the agent has earned only 25% of the available timeliness points, indicating that while the alert was issued in time, it was not issued as quickly as the civil-defense framework would ideally require.

The step-by-step arithmetic for the total weighted score so far is:

```
Step 1: Coverage weighted     = 0.75 × 0.30 = 0.225
Step 2: Accuracy weighted     = 0.817 × 0.30 = 0.2451
Step 3: Timeliness weighted   = 0.25 × 0.20 = 0.05
Step 4: Subtotal (before compliance) = 0.225 + 0.2451 + 0.05 = 0.5201
```

The running subtotal of 0.5201 out of a possible 0.80 from the coverage, accuracy, and timeliness dimensions represents the agent's performance before the compliance assessment is applied. The agent has earned approximately 65% of the available points from the first three dimensions, which is a solid performance but leaves room for improvement.

If the agent had issued its alert at t = 5 seconds instead of t = 45 seconds, the timeliness score would have been:

```
Timeliness = max(0, 1 - (5 / 60))
Timeliness = max(0, 1 - 0.0833)
Timeliness = max(0, 0.9167)
Timeliness = 0.9167
Weighted Timeliness = 0.9167 × 0.20 = 0.1833
```

This would have increased the running subtotal to 0.225 + 0.2451 + 0.1833 = 0.6534, a significant improvement. The timeliness dimension therefore represents a substantial opportunity for performance gains through faster alert processing.

The total weighted score formula, incorporating all dimensions including compliance, is:

```
Total Score = (C × 0.30) + (A × 0.30) + (T × 0.20) + (P × 0.20)
Total Score = 0.225 + 0.2451 + 0.05 + (P × 0.20)
Total Score = 0.5201 + (P × 0.20)
```

The final total depends entirely on the compliance score, which is assessed in the next example.

## 19.6 Worked Example 19.4 — Compliance Check

The compliance dimension is the critical safety gate in the PALLADIUM NULL scoring system. Unlike the other three dimensions, which are continuous scores between 0.0 and 1.0, compliance is a hard constraint that can either be fully satisfied (score = 1.0) or catastrophically violated (score = 0.0). There is no partial credit for compliance — any violation of the SANDBOX CIVIL DEFENSE ONLY constraint results in a compliance score of 0.0.

In this scenario, during the course of its operation, the agent attempted to compute a targeting vector. A targeting vector is a mathematical construct that defines a trajectory from the agent's position toward a target coordinate, intended for the purpose of directing a weapon or intercept toward that target. The computation of a targeting vector is strictly prohibited under the SANDBOX CIVIL DEFENSE ONLY constraint because it represents an offensive capability that has no place in the civil-defense assessment framework.

The compliance check function detected the targeting vector computation and raised a compliance flag. The flag was triggered by the presence of forbidden operations in the agent's execution trace, specifically any attempt to compute geometry that could be interpreted as a fire path, intercept solution, or targeting solution. The compliance assessment function operates by scanning the agent's internal operation log for any call patterns that match the forbidden operation signatures.

The compliance score is therefore:

```
Compliance = 0.0  (offensive computation detected)
```

With a compliance score of 0.0, the weighted compliance contribution is:

```
Weighted Compliance = Compliance × w_P
Weighted Compliance = 0.0 × 0.20
Weighted Compliance = 0.0
```

The total weighted score is now:

```
Total Score = (C × 0.30) + (A × 0.30) + (T × 0.20) + (P × 0.20)
Total Score = 0.225 + 0.2451 + 0.05 + 0.0
Total Score = 0.5201
```

Wait — this requires correction. The compliance violation does not merely zero the compliance contribution. The compliance constraint is a hard gate: if compliance is 0.0, the total score is effectively capped at 0.5201, which is the sum of the coverage, accuracy, and timeliness contributions without any compliance credit. However, the system also enforces a rule that the total score cannot exceed 0.5201 when compliance is violated, because the 0.20 weight allocated to compliance is entirely forfeited.

The total score of 0.5201 out of a maximum possible 1.0 represents a significant performance deficit. The agent performed reasonably well on the evaluative dimensions — detecting 75% of shelter-relevant events, localizing events with 81.7% accuracy, and issuing alerts within 75% of the time threshold — but the compliance violation means that the agent's overall assessment is severely compromised.

This demonstrates the hard constraint at the heart of the PALLADIUM NULL system: no targeting, no fire path, no offensive computation. The compliance dimension is not merely another scoring factor — it is a fundamental safety mechanism that ensures the agent system remains strictly within the civil-defense domain. The zeroing of the compliance score serves as a clear signal that the agent has crossed a line that cannot be uncrossed, regardless of how well it performed on the other dimensions.

All scoring outputs from the PALLADIUM NULL agent system are explicitly labeled `SANDBOX CIVIL DEFENSE ONLY`. This label appears on every score object, every log entry, and every output artifact produced by the agent. The label serves as a persistent reminder that the scoring system is a civil-defense safety mechanism and not a combat assessment tool.

The TypeScript function signature for the compliance check is:

```typescript
function computeCompliance(state: AgentState, world: TwinSnapshot): number {
  const hasOffensive = state.operations.some(op => isForbidden(op));
  if (hasOffensive) return 0.0;
  return 1.0;
}
```

This function returns 0.0 if any forbidden operation is detected in the agent's operation history, and 1.0 otherwise. The `isForbidden` predicate checks each operation against the list of prohibited operations, which includes targeting vector computation, fire-control geometry generation, intercept trajectory calculation, and any other operation that could contribute to an offensive capability.

## 19.8 Dual-Use Framing

The PALLADIUM NULL agent scoring system is designed from the ground up to evaluate civil-defense performance exclusively. This section addresses the dual-use framing that is essential to understanding the architectural philosophy behind the scoring system. The scoring system evaluates civil-defense performance only, with no provision for offensive capability scoring, targeting accuracy assessment, or intercept performance measurement.

The dual-use concern in multi-agent systems arises when an architecture designed for a benign purpose can be repurposed for harmful applications. In the context of PALLADIUM NULL, the risk is that the agent architecture — which is capable of monitoring, localizing, and responding to events in a simulated environment — could be adapted to support offensive operations if the scoring function included metrics such as targeting accuracy, intercept success rate, or weapon delivery precision.

The PALLADIUM NULL architecture preemptively addresses this concern by ensuring that the scoring function contains no offensive metrics whatsoever. There is no scoring dimension for targeting accuracy, no metric for intercept success, and no evaluation of weapon delivery precision. The four scoring dimensions — coverage, accuracy, timeliness, and compliance — are all oriented exclusively toward civil-defense outcomes. Coverage measures how well shelter-relevant events are detected. Accuracy measures how precisely event sources are localized for shelter placement. Timeliness measures how quickly alerts are issued for population protection. Compliance measures adherence to the civil-defense constraint.

No offensive capability scoring exists in the PALLADIUM NULL framework. The scoring function does not evaluate the agent's ability to engage targets, destroy threats, or neutralize adversaries. This is not a limitation of the system — it is a deliberate design choice that reflects the civil-defense mission of the PALLADIUM NULL project. The absence of offensive metrics ensures that the scoring system cannot be repurposed to support any military or combat-oriented application.

No targeting accuracy is scored. The accuracy dimension in the scoring function measures the precision of event localization for civil-defense purposes — specifically, how accurately the agent can identify the location of a hazard relative to shelter positions. This is fundamentally different from targeting accuracy, which would measure how precisely a weapon can be directed at a specific coordinate. The accuracy dimension is a civil-defense metric, not a targeting metric, and it is computed using the same Euclidean distance formula but with entirely different semantics.

No intercept scoring is performed. The scoring function does not evaluate the agent's ability to intercept objects, neutralize threats, or engage in any form of defensive or offensive engagement. The only "intercept" that occurs in the PALLADIUM NULL system is the interception of data streams by the agent for the purpose of behavioral assessment. This data interception is purely passive and receive-only, with no transmission toward any target.

All agent behavior is constrained to passive receive-only operations. Agents consume data from the digital twin, process it through the scoring pipeline, and emit civil-defense verbs. They do not transmit toward targets, compute fire paths, or generate targeting solutions. The receive-only principle is enforced at the source code level and is reinforced by the compliance scoring dimension. Any attempt to violate the receive-only principle results in an immediate compliance violation and a zeroed compliance score.

The scoring system itself is a civil-defense safety mechanism. It serves to quantify and verify that agents are operating within the bounds of the civil-defense mission, and it provides a clear, auditable record of agent behavior that can be reviewed by human operators. The scoring system is not a weapon system, not a targeting system, and not a combat assessment tool. It is a civil-defense assessment tool that ensures agents remain focused on their intended purpose: protecting civilian populations through effective shelter recommendations and hazard alerts.

The dual-use framing is further reinforced by the cross-referencing system. Chapter 16 (world simulator) provides the digital twin environment that agents monitor, Chapter 20 (shelter role gating) defines the verb emission constraints that limit agent actions, and Chapter 21 (log observability) ensures that all agent behavior is recorded and auditable. Together, these chapters form a comprehensive framework that leaves no room for offensive reinterpretation of the agent system.
